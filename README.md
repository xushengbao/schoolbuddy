# 校园助手（SchoolBuddy）微信小程序

面向中小学教师的一体化校园管理小程序：课表、换课审批、学生状态、教师状态、班级通知与配置管理。

## 功能模块

### 一、主界面
- **日期时间**：实时时钟、日期与星期、问候语，顶部显示所属学校
- **课程表（双版本）**
  - 教师版：显示当天全部课程，换课记录以「已换课」标记突出；显示当前/下一节课倒计时
  - 班级版：显示本班当天课表、班级通知、今日学生状态汇总
- **备忘录**：可自行编辑、勾选完成、按角色隔离（教师与班级各自独立）
- **当前课时学生状态**：当前有课的班级直接展示不在位学生数量与状态

### 二、课程管理
- 管理员上传各班级课表，形成全校总课表
- 三种视图：我的课表 / 全校总课表 / 换课申请
- **班级课表为一周视图**：行=节次（含时间）、列=星期一至星期五，**一屏看完一周无需拖动**；
  今天所在列高亮，参与换课的格子标黄并带「换」角标，点格子看教师与换课说明
- 格子里教师姓名显示**全名**，超长科目用两字简称（详见「课表格子」），完整信息点开看详情
- 任课老师可查看所任教班级与任课老师
- **换课流程**：选两节课对调 → 选接收老师与他的那节课 → 发送申请 →
  接收方站内信 → 同意或拒绝（拒绝可填备注）→
  同意后**双方教师 + 两个班级的班主任**各收一条站内信，班级课表与教师课表立即体现换课结果
- **撤销**：待处理、已同意两个状态下双方都能撤销；撤销已生效的换课会让课表恢复原样
- **课程提醒**：每节课上课前 10 分钟以站内信提醒任课老师

### 三、学生管理
- Excel/CSV 导入学号与姓名
- **学生状态**：病假、事假、医务室、其他（管理员可自定义选项）
- 支持「全天状态」与「第 N 节课状态」两级粒度
- 汇总展示总状态人数与分节状态，教师查看任课班级任意时段状态

### 四、教师管理
- Excel/CSV 导入教师账号、密码、学科组
- 教师登录后可自行修改密码
- 学科组分组：语文组、数学组、英语组等
- **教师状态**：在位中（默认）、请假中、公出中、开会中；教师可自行修改，也可查看全校教师状态

### 五、消息功能
- 教师向任教班级发送消息
- **静默文字**（仅显示）与**语音自动播报**两种形式
- 班级通知大屏页面，支持逐条或自动连续播报

### 六、配置功能

**三级权限**

| 角色 | 账号来源 | 可做什么 |
|---|---|---|
| 超级管理员 | 初始内置 `597280879` / `Xu3320782*` | 平台管理页：添加学校、添加/查看学校管理员、提升教师为管理员、退出登录 |
| 学校管理员 | 由超级管理员在「学校模版」中指定 | **导入学生 / 班级 / 课表 / 教师 / 班级账号** |
| 教师 / 班级 | 各校自行导入 | 日常教学使用 |

- 「学校配置」区块**仅超级管理员可见**，登录后直达该页面
- 导入学生、班级、课表等数据**仅学校管理员可操作**，普通教师与班级账号会被拦截
- 登录页不再显示任何初始账号提示
- 登录后各页面顶部展示所属学校名称

**平台管理页（仅超级管理员）**

- 顶部身份条显示姓名与账号，右侧「退出登录」
- 学校列表点选后，页面下方实时显示**该校的管理员账号**（姓名、组别、状态、登录账号），点账号即复制
- 支持用学校模版一键导入学校 + 管理员，也可手动只建学校、或把校内已有教师账号提升为管理员

**学校管理员可配置项**
- 学生状态选项自定义
- 作息时间设置（**默认一天六节课**，与课表模版一致：
  ① 08:20-09:00 ② 09:15-09:55 ③ 10:25-11:05 ④ 11:20-12:00 ⑤ 13:20-14:00 ⑥ 14:15-14:55；
  管理员改过后以自定义为准，不再被默认覆盖）
- 班级课表 / 教师课表 / 学生名单 / 教师名单 / 班级账号 导入
- 调休设置（把某个周六/周日设为按某个工作日的课表上课）
- 删除教师、删除班级（含其课表与名单）、清空某班课表

改课表内容的方式只有一个：**重新导入更新后的课表文件**（见「修改课表的方式」）。

**其他入口约定**
- 登录页与「修改密码」页的密码框都有「显示 / 隐藏」按钮
- 数据导入只在**配置中心**提供一处，「我的」页不再重复放入口

## 导入格式

小程序内置了三套表格解析器，**Excel 原文件可直接导入，无需另存为 CSV**：

| 格式 | 解析方式 |
|---|---|
| `.xls`（Excel 97-2003） | `utils/xls.js`：OLE2 复合文档 + BIFF8 记录（含 SST 跨记录续读） |
| `.xlsx`（Excel 2007+） | `utils/xlsx.js` + `utils/inflate.js`：ZIP 中央目录 + XML，纯自研 DEFLATE 解压 |
| `.csv` / `.txt` | `utils/excel.js`：UTF-8 解码 + 分隔符切分 |

导入页读取后会显示工作表清单与首个工作表前 5 行预览，确认无误再点「开始导入」。

| 模版 | 必需表头 / 结构 |
|---|---|
| 学校模版 | 学校、管理员、组别、账号、密码（每行同时建学校 + 该校管理员） |
| 班级课表模版 | 矩阵式：每个工作表 = 一个班级（sheet 名或 A1 单元格），列 = 星期一…星期五，科目行与「时间 + **教师**」行成对 |
| 教师课表模版 | 矩阵式：每个工作表 = 一位教师（sheet 名即教师姓名），列 = 星期一…星期五，科目行与「时间 + **班级**」行成对 |
| 学生模版 | 每个工作表 = 一个班级，表头含 学校、班级、姓名、学号 |
| 教师账号模版 | 学校、教师姓名、组别、账号、密码 |
| 班级账号和密码模版 | 账号、学校、班级、密码、**班主任账号**（表头按名称匹配，列顺序可调整） |

对应 CSV 模版在 `templates/`（`课表模版.csv` 已拆为 `班级课表模版.csv` 与 `教师课表模版.csv`）。

### 导入要点

- **两种课表互相补充**：班级课表认「谁教」，教师课表认「教谁」。两份都导入时任课关系最完整；
  同一班同一节次以最后一次导入为准，不会重复建行。
- **班级名自动归一**：课表里写「B五1班」、账号与学生模版里写「B五1」，都能对上同一个班。
- **班主任绑定**：班级账号模版的「班主任账号」填教师账号后，会自动写入该班的班主任，
  班主任即可收到本班换课通知与学生状态提醒。留空则不覆盖已有绑定。
- **自动建班**：课表与学生导入遇到不存在的班级会自动创建，无需事先建班级。
- **教师未匹配只提示不阻断**：班级课表里出现教师名单中没有的老师，课表照常导入，
  但会列出缺失名单，导入教师账号后重导一次即可完成认课。
- **不降级管理员**：导入教师名单时，已是学校管理员的账号会保留管理员角色。
- **幂等**：重复导入同一份文件是安全的，学校、账号、课表、名单均复用更新而非重复创建。
- **批量写入**：导入不再逐条查询与插入。先一次性拉取已有数据在内存里比对，
  新增的行按 50 条一片批量写入，更新请求并发上限 8。
  120 条课表 + 132 名学生的导入，数据库调用从 250+ 次降到 20 次左右，弱网下体感提升明显。

### 换课数据模型

`swap_requests` 一条记录表示「两节课对调」：

| 字段 | 含义 |
|---|---|
| `class_id` / `weekday` / `period_no` / `subject` | 第一节：发起方想让出去的课 |
| `swap_class_id` / `swap_weekday` / `swap_period_no` / `swap_subject` | 第二节：接收方让出来、由发起方接手的那节课 |
| `swap_teacher_id` / `swap_teacher_name` | 第二节原本的任课老师（同意后即发起方本人） |

课表呈现统一由 `utils/school.js` 的 `buildSwapOverlay(schedules, swaps, teacherMap)` 生成覆盖表，
所有页面（班级周课表、我的课表、全校总课表、教师详情）都读同一份结果，不会出现某个页面显示不一致。

- 星期支持「周一」「星期一」「1」；节次支持「第1节」「1」
- 表头名称有小幅差异（如「教师」/「任课教师」）也可识别
- 账号、学号在 Excel 里是数字型时会自动转字符串，不会变成 `1.7651e+10`

## 语音播报说明

语音播报依赖微信官方「微信同声传译」插件（WechatSI）。**该插件默认未启用**，
通知会以醒目的文字卡片展示（「最新」徽标 + 高亮边框），内容不会丢、不会静默失败。

### 为什么默认关闭

小程序使用插件需要**两个条件同时满足**：

1. 微信公众平台 → 管理 → 设置 → 第三方设置 → 插件管理 → 已获批「微信同声传译」
2. `app.json` 里声明了 `plugins.WechatSI`

关键点：**只能先满足第 1 条，才能加第 2 条**。如果后台还没给这个小程序开通该插件，
却在 `app.json` 里声明了它，代码上传阶段就会直接失败：

```
upload failed: Error: {"errCode":-1,
"errmsg":"inner upload fail with errcode: 80082, errmsg: get plugin ..."}
```

（`80082` = 插件无权限 / 不存在。）本项目当前处于「尚未开通」状态，所以
`app.json` 里没有这段声明，代码里也用开关关掉了。

### 如何启用

确认第 1 条已获批后，改两处即可，页面代码无需任何改动：

1. `utils/tts.js` 顶部：`const PLUGIN_ENABLED = false` 改成 `true`
2. `app.json` 的 `window` 同级加上：

```json
"plugins": {
  "WechatSI": {
    "version": "0.3.5",
    "provider": "wx069ba97219f66d99"
  }
}
```

> ⚠️ 两条必须一起改。只改第 2 条（加声明）而插件未获批，会重现 80082 上传失败。

### 一条绕不过去的微信限制

微信规定**音频的首次播放必须由用户手势触发**。所以「大屏一进页面就自动开口」
在任何小程序里都做不到 —— 这不是代码问题。

因此大屏页顶部有「🔊 点此开启语音播报」引导条，点一次之后，教师后续发来的语音
通知才会自动朗读。已处理静音键（`obeyMuteSwitch: false`），教室关静音也能听到。

## 消息实时同步说明

小程序没有可用的推送通道（云服务 SDK 也不提供推送），所以班级端采用**轮询**：

| 页面 | 间隔 | 说明 |
| --- | --- | --- |
| 班级通知大屏 | 5 秒 | 常驻投影，必须最快 |
| 班级首页 | 10 秒 | 顺带更新消息卡片 |
| 教师发送页 | 手动 | 下拉刷新 |

实现要点（`utils/message-sync.js`）：

- 页面 `onHide` / `onUnload` 立即停轮询，不在后台空耗
- 切回前台立刻补拉一次，避免错过后台期间的新消息
- 慢请求不重叠发起，弱网下不会堆积
- 内容未变化时跳过 `setData`，大屏不会每秒闪一次
- 每条语音只自动播一次（`spokenIds` 去重），不会反复朗读同一条

## 课表格子

课表网格（班级课表 / 教师课表 / 教师详情）刻意压得很窄，让周一到周五**一屏看全，不需左右拖动**。

| 位置 | 宽度 |
| --- | --- |
| 节次列 | 76rpx |
| 每个星期列 | 约 125rpx（`750 - card padding 48 - 节次 76` ÷ 5） |
| 格子内可用 | 约 117rpx（扣掉边框与内边距） |

关键样式（`app.wxss` 的 `.grid` 系列）：

- `.grid` 不再设 `min-width`，改为 `width: 100%`，跟着屏宽自适应
- 格子与文字统一 `white-space: nowrap` + `overflow: hidden` + `text-overflow: ellipsis`
- **去掉了原来的 `word-break: break-all`** —— 它会把「语文」竖着排成两行

### 简称的使用边界

| 内容 | 显示方式 | 例 |
| --- | --- | --- |
| **教师姓名** | **全名，不简称** | 周老师、许晓峰、欧阳修 原样显示 |
| 科目 | 超 4 字才压成两字 | 道德与法治 → 道法 |
| 班级名 | 去掉年级前缀 | 三年1班 → 1班，六(3)班 → (3)班 |

**为什么教师名不简称**：19rpx 字号下 117rpx 能放 6 个汉字，而实际数据里
最长也只有 3 字（`teachers.name` max length = 3），简称反而丢信息。
曾经加过 `shortTeacher()`（周老师 → 周），用一轮就撤掉了 ——
压得过头不是优化，是信息损失。真实超长名字（7 字以上）由 `text-overflow` 兜底省略。

测试里有宽度断言守着这条边界：`教师全名在列内放得下（≤6 字）`。

「全校总课表」的班级×节次矩阵横向是**全部班级**，数量不受控，保留横向滚动，
但列宽从 150rpx 压到 108rpx。

## 修改课表的方式

**只有一条路：重新导入更新后的课表文件。**（曾有的「课表微调」功能已下线。）

导入是 **upsert + 清理** 两步：

1. 逐格写入 —— 新增或更新（内容没变则跳过请求，重复导入几乎零开销）
2. **清理** —— 算出「旧表里有、新文件里已经没有」的格子并删除

第2 步很关键：没有它的话，用户在新文件里删掉一节课再上传，那节课会永远留在库里，
「重新上传即可」就成了摆设。清理只作用于**本次上传涉及的班级**，其他班不受影响。

## 跨班换课的显示

`buildSwapOverlay(schedules, swaps, teacherMap, classId)` 曾经有个隐蔽的 bug：

换课经常跨班（A班第一节 ⇄ B班第一节）。传了 `classId` 时，函数在**建原始格子**阶段
就按班级过滤掉，于是换课涉及的两个格子只剩本班那个，对方那格由 `ensure()` 造出来是空的：

```js
c1.subject = before.s2 || before.s1   // before.s2 是空 → 退化成原科目
```

表面看没报错，实际表现就是**换过的格子只打个「换」标记，科目和老师都不对**。

现在改成：**过滤只作用于「最终返回哪些格子」，不参与计算过程**。并且去掉了 `||` 兜底 ——
「对方那格本来就是空课」和「取值为空」是两件事，空就是空，不能悄悄保留原科目。

所有调用点（`getScheduleForDay`、班级课表页）都改为传**全校** `schedules`，
只靠第四个参数筛选返回结果。

## 调休设置（仅学校管理员）

**入口：配置中心 → 状态与作息 → 调休设置**

把某个**周六或周日**设为「按某个工作日的课表上课」。例如 10 月 17 日（周六）
设为按周一上课，当天全校老师与班级看到的就都是周一的课表。

| 字段 | 说明 |
| --- | --- |
| 日期 | 只能用 date 选择器，只能对周末生效（周一到周五本来就有课） |
| 按哪天上 | 周一至周五选一 |
| 备注 | 选填，如「国庆补课」 |

弹层内会实时预览当天各节次的科目，避免设错。

**设计要点**：落库只记一条「哪一天 → 顶哪个星期几」，**不复制课表数据**。
所以调休日永远跟着基准课表走 —— 之后重新导入了新课表，调休日自动跟着变，
不存在「调休日课表忘了同步」的问题。

生效范围：`getScheduleForDay()` / `getTeacherDaySchedule()` 内部统一走 `resolveDay()`
解析，首页、教师课表、班级首页、班级大屏、课程提醒全部自动生效。
教师首页与班级首页会显示橙色提示条「调休日，按周一课表上课」，
课程页日期标签也会带同样说明 —— 否则周六看到有课会以为系统坏了。

数据极小（一学期十几条），模块内缓存 60 秒，保存/取消后手动失效。

## 换课语义

换课永远是「**我 ⇄ 其他老师**」，不存在自己和自己换。

实现要点：

- 候选生成统一走 `buildSwapCandidates()`（`utils/school.js`），判断「这节课是谁的」
  **只认 `buildSwapOverlay()` 的结果**，不看 `schedules.teacher_id` 原始值 ——
  换过一次课后两边口径必须一致，否则发起方自己的课会出现在别人候选里（历史 bug）
- 候选生成时直接 `if (tid === requesterId) return` 排除自己
- 已参与有效换课的格子不再作为候选；停用教师不列入候选
- 客户端 `submitSwap()` 三道校验 + 服务端 `createSwapRequest()` 三道闸，
  防止构造请求绕过页面直接「自己换自己」

### 换课冲突拦截

对调是「两节课互换格子」，所以要查两个方向的冲突。判断依据同样是
`teacherBusyAtSlot()`（跨班级算，同一老师同一节只能在一个班）：

| 情况 | code | 结果 |
| --- | --- | --- |
| 被申请的老师在**第一节课的节次**上已有课 | `target_busy` | 拒绝发起 |
| 发起方在**第二节课的节次**上已有课 | `requester_busy` | 拒绝发起 |
| 选到自己 | `self` | 拒绝发起 |

- 候选生成阶段：冲突的老师**保留在列表里但整位禁用**，上方显示橙色原因条
  （如「周一第1节已有三年2班 英语，不能再接这节课」）。
  直接隐藏会让用户以为系统漏了这个人。
- 提交前 `submitSwap()` 再校验一次并给出可读提示
- 服务端 `createSwapRequest()` 同样拦截 —— 申请是可以被构造的

### 撤销

**待处理**和**已同意**两个状态下，双方（发起方 + 接收方）都能撤销：

| 状态 | 可撤销方 | 效果 |
| --- | --- | --- |
| `pending` | 双方 | 申请作废，课表无变化 |
| `approved` | 双方 | **课表恢复原样**（`status` 改为 `cancelled` 后自动退出 `buildSwapOverlay` 的输入） |
| `rejected` / `cancelled` | — | 终态，不再可撤 |

撤销入口有两处：换课详情页的「撤销这次换课」按钮，以及课程页列表行内的「撤销」
（`catchtap` 拦住冒泡，不用进详情页）。

**恢复原样为什么不需要额外回滚**：`buildSwapOverlay()` 只吃 `status='approved'` 的换课单，
把状态改成 `cancelled` 之后这节课自动不在 overlay 输入里，两个格子自然回到原始的
`schedules` 数据。不存在「撤销要写回课表」这种容易出错的动作。

### 通知矩阵

所有换课通知统一走 `notifySwap(row, event, options)`，收件人规则集中在一处：

| 事件 | 发起方 | 接收方 | 两个班级的班主任 |
| --- | :---: | :---: | :---: |
| `apply` 收到申请 | ✓ | ✓ | — |
| `approve` 已同意 | ✓ | ✓ | ✓ |
| `reject` 被拒绝 | ✓ | — | — |
| `cancel` 撤销（未生效） | ✓ | ✓ | — |
| `cancel` 撤销（已生效） | ✓ | ✓ | ✓ |

几条约定：

- 换课常跨两个班级（第一节在 A 班、第二节在 B 班），**两班班主任都要通知**；
  `swap_class_id` 缺失时回落到 `class_id`，并对班主任去重
- 班主任恰好是换课双方之一时，只作为「双方」收一条，不重复发「班主任那条」
- `reject` 时**操作人自己不发** —— 他刚点的拒绝，再收一条「被拒绝」是噪音
- 单条通知失败不影响其他收件人，也不影响换课本身（逐条 try/catch）

## 数据存储

数据保存在 WorkBuddy 云服务中，共 11 张表：教师、班级、学生、课表、
换课申请、**调休日**、学生状态、站内信、班级消息、备忘录、系统配置。
密码以散列形式存储，不保存明文。

### 提交前必跑

```bash
node _verify.js                        # 静态校验（见下）
for f in test/*.js; do node "$f"; done # 全部测试
```

`_verify.js` 有 5 类检查，最后一类是**踩过坑之后加的**：

| # | 检查 | 查什么 |
| --- | --- | --- |
| 1 | 语法 | 能否被编译 |
| 2 | JSON | 配置是否合法 |
| 3 | 事件处理函数 | WXML 里的 `bindtap` 等在 JS 里有没有对应方法 |
| 4 | exports 匹配 | `import { x }` 的 x 在目标模块里真的导出了吗 |
| 5 | **自由函数作用域** | 调用了 `utils/school` / `utils/util` 的函数，但**忘了 import** |

第 5 条是被真实白屏事故逼出来的：`pages/schedule/schedule.js` 调了
`shortClassName()` 却漏了 destructure，运行时 `TypeError` 导致整个「全校总课表」白屏，
而前 4 条检查**全部通过** —— 它们只验「有没有写」，不验「引用的东西在不在作用域里」。

要验证它真的有效，可以手动删掉任一 import 看是否报错。
